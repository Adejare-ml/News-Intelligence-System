Run `30763382713` then went green with article analysis via Ollama and report generation via NVIDIA, confirming both keys were valid. **PR #16 (merged)** implemented the hardening. `JWT_SECRET` lost its default and the API now refuses to start without one, rejecting known placeholder values and secrets under 32 chars; `.env.example` ships blank. Admin seeding requires `ADMIN_SEED_PASSWORD`. Token lifetime went 7 days → 24 hours; a malformed `sub` claim returns 401 instead of 500. docker-compose binds Postgres and Redis to `127.0.0.1`. CDN scripts are version-pinned with SRI (chart.js 4.5.1, vis-network 9.1.9, lucide 1.28.0) and the unpinned unpkg fallback removed; third-party Actions are pinned to commit SHAs. CSV export gained formula-injection guards and Google News RSS is fetched via `requests` with a 15s timeout (feedparser has none).

That diff was reviewed by a 4-lens adversarial Workflow (25 agents, 21 raw findings). It reported **0 confirmed**, which was not trusted because the verifier prompt said "default to refuted=true if uncertain"; manual checking found three real defects. `safeUrl()` validated only the scheme while its output was interpolated into a quoted `href` where quotes were never escaped, so `https://evil.com" onmouseover="…` passed the check and broke out of the attribute — an XSS hole inside the guard meant to prevent one. It was split into `safeUrl` (DOM property assignment, query strings intact) and `safeUrlAttr` (HTML interpolation, escaped). `art.source` was written raw to `innerHTML`. The strict CSP would have broken FastAPI's `/docs` (Swagger needs an inline script and jsdelivr CSS), so docs routes got a scoped policy. `.env.example`'s committed placeholder satisfied the fail-fast check, producing a publicly known signing key. The CSV guard skipped the ID and Risk Score columns, and `encodeURI` on a `data:` URI silently truncated exports containing `#` (replaced with a Blob). A meta-tag CSP was added to `index.html` because GitHub Pages — the primary deployment — cannot send headers.

The dossier was **entirely dead in production**: PSC rows used inline `onclick`, which the CSP from PR #16 blocks — browser verification confirmed 7 rows rendering, inline handler present, click doing nothing. The dossier's Copy JSON button interpolated `JSON.stringify(record)` into an `onclick` attribute and was rebound. A `psc-demo-banner` was added, shown only when no live disclosures exist.

**PR #18 (merged, `274178e`) — workflow concurrency.** Run `30806786258` went red with `error: failed to push some refs`. The cause was a race, not a pipeline fault: the cron run `30806572937` started 10:41:42 and the manual run started 10:44:58; both completed their pipeline steps successfully, the cron run pushed `fff7069` at 10:55:04, and the manual run's push 33 seconds later was rejected as non-fast-forward from a now-stale checkout. Only the second run's commit and its gh-pages deploy were lost; no data was lost because both runs wrote to Google Sheets and the JSON exports regenerate from the sheet each run. `news_scheduler.yml` gained `concurrency: {group: news-pipeline, cancel-in-progress: false}` — cancellation is deliberately off because killing a run mid-analysis abandons articles whose LLM quota was already spent and the Sheets writes are not transactional. `deploy_pages.yml` gained a separate `concurrency: {group: pages-deploy, cancel-in-progress: true}`; both workflows write the `gh-pages` branch, but the groups were kept distinct because GitHub keeps only one pending run per group, so a shared group would let a docs deploy supersede a queued ingestion run and silently skip a collection cycle.
